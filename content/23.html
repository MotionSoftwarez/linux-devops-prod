Module 1, Lesson 22 — Containers and Docker Foundations on Linux

Level: Intermediate · Estimated time: 35–45 minutes · Practical focus: container basics

In this lesson, you’ll learn what containers are, how they differ from virtual machines, how to install Docker on Ubuntu, run and manage containers, and inspect container logs and resources. Containers are the foundation behind modern DevOps and Kubernetes.

1. What is a container?

A container packages an application with its libraries, dependencies, and configuration into a single isolated unit. It runs as an isolated process on the host Linux kernel.

Containers vs virtual machines:

Container Virtual Machine
Shares host kernel Yes No
Startup time Seconds Minutes
Disk image size Megabytes Gigabytes
Isolation Process-level Full hardware

Containers are lightweight because they don’t boot a full operating system — they use Linux kernel features (namespaces and cgroups) for isolation and resource limits.

2. Install Docker on Ubuntu

sudo apt update
sudo apt install -y docker.io

Start and enable Docker:

sudo systemctl start docker
sudo systemctl enable docker

Verify Docker is running:

sudo systemctl status docker

Run Docker without sudo (optional, add your user to the docker group):

sudo usermod -aG docker $USER

Then log out and back in for the group change to take effect.

3. Run your first container

Download and run the Nginx image:

docker run -d -p 8080:80 --name my-nginx nginx

What this does:

  • -d — run in the background (detached).
  • -p 8080:80 — map host port 8080 to container port 80.
  • --name my-nginx — give the container a name.
  • nginx — the image to use.

Test it:

curl http://localhost:8080

You should see the Nginx welcome page HTML.

4. Manage containers

List running containers:

docker ps

List all containers (including stopped):

docker ps -a

Stop a container:

docker stop my-nginx

Start a stopped container:

docker start my-nginx

Remove a stopped container:

docker rm my-nginx

Remove a running container (force):

docker rm -f my-nginx

5. Inspect containers

View container logs:

docker logs my-nginx

Follow logs in real time:

docker logs -f my-nginx

Inspect container details:

docker inspect my-nginx

Run a command inside a running container:

docker exec -it my-nginx bash

Type exit to leave the container shell.

6. Images

List downloaded images:

docker images

Remove an image:

docker rmi nginx

Pull an image without running it:

docker pull alpine

8. Realistic DevOps case study: run a temporary test web server

Scenario: You need a quick web server to test an application deployment, but you don’t want to install Nginx directly on the host.

Run a throwaway container:

docker run -d -p 9090:80 --name test-web nginx
curl http://localhost:9090

When testing is done, remove it completely:

docker rm -f test-web

Because it was a container, nothing is left installed on your host.

10. Cheat sheet — Docker essentials

Task Command
Install Docker sudo apt install docker.io
Start Docker sudo systemctl start docker
Status sudo systemctl status docker
List images docker images
List running containers docker ps
List all containers docker ps -a
Run detached docker run -d -p 8080:80 --name c nginx
View logs docker logs c
Follow logs docker logs -f c
Exec into container docker exec -it c bash
Stop container docker stop c
Remove container docker rm c
Remove force docker rm -f c
Remove image docker rmi image

Safety tip: Containers are isolated from the host, but processes running as root inside a container still have capabilities. Prefer running containers as a non-root user where possible.
