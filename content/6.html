Linux permissions and ownership: chmod, chown, chgrp, and umask

Beginner

Hands-on lab

Production safety

Linux permissions control who can read, modify, or execute a file. Ownership determines which user and group a file belongs to.

These concepts are essential in DevOps when deploying applications, running services, sharing files between team members, and troubleshooting Permission denied errors.

1. Understand Linux permissions visually

Imagine a web application deployment directory:

/var/www/myapp

Owned by user deploy, group webteam

Owner

User who owns the file

Group

Users in the assigned group

Others

Everyone else

Linux evaluates access according to the file's permission bits and the user's relationship to its owner and group, along with other security controls.

For a file, these three permission classes are:

  • Owner (u) — the file's owner.
  • Group (g) — users belonging to the file's group.
  • Others (o) — users who are neither the owner nor members of the assigned group.
  • All (a) — shorthand for owner, group, and others when using symbolic permission commands.

3. Numeric permissions: understand 755, 644, and 700

Linux can represent r, w, and x with numbers:

Permission Value
Read (r) 4
Write (w) 2
Execute (x) 1
No permission (-) 0

Add the values for each class.

For example, rwx = 4 + 2 + 1 = 7. r-x = 4 + 0 + 1 = 5. r-- = 4 + 0 + 0 = 4.

4. Change permissions with chmod

chmod means change mode. It changes file or directory permission bits.

Numeric method

chmod 644 app.conf
chmod 755 deploy.sh
chmod 700 private-dir

Interpretation:

  • chmod 644 app.conf — owner can read and write; group and others can read.
  • chmod 755 deploy.sh — owner can read, write, and execute; group and others can read and execute.
  • chmod 700 private-dir — only the owner receives permissions through the basic mode bits.

Symbolic method

Symbolic permissions use:

  • u = owner
  • g = group
  • o = others
  • a = all
  • + = add permissions
  • - = remove permissions
  • = = set the specified permissions for that class

Examples:

chmod u+x deploy.sh
chmod g-w app.conf
chmod o-r secret.txt
chmod u=rw,g=r,o= app.conf

What they mean:

Command Effect
chmod u+x deploy.sh Adds execute permission for the owner
chmod g-w app.conf Removes group write permission
chmod o-r secret.txt Removes read permission from others
chmod u=rw,g=r,o= app.conf Sets owner to read/write, group to read, others to no permissions

Numeric vs symbolic: Numeric modes are convenient when you know the complete target mode. Symbolic modes are useful when you want to change just one permission without intentionally changing the others.

Directories and recursive changes

chmod 750 /srv/myapp

This changes permissions on the specified directory itself.

chmod -R 750 /srv/myapp

This recursively applies the mode to the directory and its contents. That can be dangerous: executable files, ordinary files, and nested directories often need different modes. Avoid broad recursive permission changes unless you have inspected the tree and planned the correct modes.

5. Change ownership with chown

chown means change owner.

Check current ownership first:

ls -l app.conf

Example:

-rw-r--r-- 1 root root 120 Oct 25 10:00 app.conf

Here the owner is root and the group is root.

Change the owner:

sudo chown deploy app.conf

Change both owner and group:

sudo chown deploy:webteam app.conf

Change only the group using chown:

sudo chown :webteam app.conf

For a directory tree:

sudo chown -R deploy:webteam /srv/myapp

-R means recursive. Be particularly careful with recursive ownership changes on production servers because they may affect files the operating system or application expects to own.

6. Change group ownership with chgrp

chgrp means change group.

sudo chgrp webteam app.conf

This changes the file's group to webteam, leaving the owner unchanged.

For a directory tree:

sudo chgrp -R webteam /srv/myapp

Use recursive changes only when every affected file and directory should belong to that group.

Compare the commands

Command Primary purpose
chmod Change permissions
chown Change owner; optionally group
chgrp Change group
umask Set default permission restrictions for newly created files and directories

Changing ownership and changing permissions are different operations. A file can have the correct owner but still lack the permissions a service needs.

7. Understand umask: default permission restrictions

When a process creates a file or directory, Linux uses the process's creation mode together with its umask to determine the initial permissions.

Think of umask as a filter that removes permissions from the requested defaults.

Requested default mode

666 for files

Read and write for owner, group, and others

Apply umask 022

Remove group-write and others-write permissions

Result for a regular file

644

Owner read/write; group and others read

A key detail: normal file creation modes typically start at 666 and directory creation modes at 777. The execute bits are not normally requested for a newly created regular file, so umask doesn't automatically make a new script executable.

Check your current umask

umask

For a more detailed symbolic representation on many Bash/Linux setups:

umask -S

Set umask for the current shell

umask 022

This affects files and directories subsequently created by processes launched from that shell, subject to the creation mode requested by each program.

Common examples

Umask New regular file, typical New directory, typical
022 644 755
027 640 750
077 600 700

These are the usual results when the program requests modes 666 for a file and 777 for a directory.

Safety tip: umask is not a replacement for reviewing permissions on an existing file. Changing the umask does not modify files already created. Also, a program can explicitly change permissions after creation.

8. Realistic DevOps case study: fix Permission denied

Scenario: A deployment script is present on the server, but the deployment user cannot run it.

The practice file is ~/devops-lab/lesson5/deploy.sh.

Step 1 — Inspect the file

ls -l ~/devops-lab/lesson5/deploy.sh

Suppose the output is:

-rw-r--r-- 1 deploy webteam 85 Oct 25 10:00 deploy.sh

The owner has read and write permission but no execute permission.

Step 2 — Add execute permission for the owner

chmod u+x ~/devops-lab/lesson5/deploy.sh

Verify the result:

ls -l ~/devops-lab/lesson5/deploy.sh

The permission string should now begin with -rwx.

Step 3 — If access still fails, inspect ownership and the path

id
namei -l ~/devops-lab/lesson5/deploy.sh
  • id shows your user and group memberships.
  • namei -l displays the path components and their permissions on systems that provide it.

The script may be executable but still inaccessible if the user cannot traverse a parent directory, or if the filesystem is mounted with noexec.

Step 4 — Fix the actual issue, not everything at once

If the deployment team requires group access, verify the intended group before changing ownership or permissions. For example, an authorized administrator might set the group to webteam and grant the group the needed access.

sudo chgrp webteam ~/devops-lab/lesson5/deploy.sh
chmod 750 ~/devops-lab/lesson5/deploy.sh

This example allows the owner to read/write/execute, the group to read/execute, and others no access. Use it only if those are the intended access requirements.

Production safety checklist

  • Inspect with ls -l before changing anything.
  • Confirm which user runs the service or deployment.
  • Check parent-directory permissions as well as the target file.
  • Apply the narrowest permission change that solves the issue.
  • Avoid using chmod 777 as a shortcut.
  • Avoid recursive changes to /, /etc, /usr, or application trees without a reviewed plan.
  • Verify the result and test with the appropriate service account when authorized.

Permission denied is a symptom. Find out which access check failed before changing permissions.

9. Interactive practice lab

Use this lab on your own Linux machine or in a disposable environment. The commands create files under ~/devops-lab/lesson5 and do not require root privileges.

Step A — Create a practice file

mkdir -p ~/devops-lab/lesson5
cd ~/devops-lab/lesson5
printf '#!/bin/sh\necho Deployment practice\n' > deploy.sh
ls -l deploy.sh

Step B — Explore symbolic permissions

Try the commands below one at a time. After each command, run ls -l deploy.sh and observe the changes.

1. Remove execute permission from everyone

chmod a-x deploy.sh

No execute bit should remain for owner, group, or others.

2. Give the owner execute permission

chmod u+x deploy.sh

The owner's permission group should contain x.

3. Remove write permission from group

chmod g-w deploy.sh

The group's permission group should not contain w.

4. Set mode to 750 numerically

chmod 750 deploy.sh

The mode should show rwx for owner, r-x for group, and --- for others.

Tick a step after running and checking it in your terminal. The checklist does not execute commands for you.

Step C — Practise ownership and umask safely

Inspect your account and current default mask:

id
umask

Create a test file after setting a temporary umask:

umask 077
touch private-test.txt
ls -l private-test.txt

The new file will typically have mode 600 under this umask when created with the normal file-creation mode. Verify rather than assume.

You can restore the usual mask for your current shell with:

umask 022

For ownership practice, inspect the current owner and group with ls -l. Only use chown or chgrp on files you own or are explicitly authorized to change. On some systems, changing ownership requires administrator privileges.

12. Final cheat sheet

Permissions quick reference

Copy commands

Command Purpose
ls -l file Inspect mode, owner, and group
id Check user and group memberships
chmod 644 file Set owner read/write; group and others read
chmod 755 script.sh Set owner full access; group and others read/execute
chmod u+x script.sh Add execute permission for owner
chmod g-w file Remove group write permission
chmod 750 directory Restrict access to owner and group
chown user file Change owner
chown user:group file Change owner and group
chgrp group file Change group
umask Display the current mask
umask 022 Set the current shell's mask to 022
umask 027 Set the current shell's mask to 027

Remember these rules

  • r = 4, w = 2, x = 1.
  • chmod changes permissions; chown and chgrp change ownership metadata.
  • umask influences default permissions when new files and directories are created.
  • Directories generally need execute permission for traversal.
  • Avoid chmod 777 as a generic fix.
  • Inspect first, make the smallest appropriate change, then verify.
