Linux for DevOps — Module 1, Lesson 3

Create, Copy, Move, and Delete Files

This lesson covers five essential Linux commands: mkdir, touch, cp, mv, and rm. You'll practise them using a DevOps-style deployment scenario, with a simulated lab, a quiz, an assignment, and a quick-reference cheat sheet.

Beginner

Hands-on lab

Production safety

Learning objective: Create a project directory, prepare files, back up a configuration, move files into an archive, and safely clean up test files.

1. The five commands at a glance

Command Meaning Example
mkdir Make a directory mkdir project
touch Create an empty file, or update its timestamp touch app.conf
cp Copy a file or directory cp app.conf app.conf.bak
mv Move or rename a file or directory mv old.txt new.txt
rm Remove files or directory trees rm -i old.txt

Imagine your application files are stored in folders:

myapp/

app.conf

deploy.sh

The commands below let you create this structure, duplicate its files, reorganize them, and remove unneeded items.

2. Create directories with mkdir

A directory is a folder that holds files and other directories.

mkdir project

This creates a directory called project in your current location.

To create nested directories:

mkdir -p project/config/nginx

The -p option creates missing parent directories too.

Resulting directory tree

project/
└── config/
└── nginx/

Check your location and the new directory:

pwd
ls -lah
ls -ld project
  • pwd displays your current directory.
  • ls -lah lists files, including hidden files, in a readable long format.
  • ls -ld project shows details about the directory itself.

3. Create files with touch

touch app.conf
touch deploy.sh
touch README.txt

These commands create empty files if they don't already exist.

Create several files at once:

touch app.conf deploy.sh README.txt

Important: If a file already exists, touch normally updates its timestamps; it does not erase the file's contents.

To add content to a practice file:

echo "APP_ENV=development" > app.conf

Be careful: > overwrites existing content. To append a line instead, use >>.

4. Copy files with cp

Copy a configuration file to make a backup:

cp app.conf app.conf.bak

The original remains in place, and a second file is created.

app.conf — original

app.conf.bak — copied file

The two files are separate copies. Editing one does not automatically update the other.

Copy a file into another directory:

mkdir backups
cp app.conf backups/

Copy a directory and its contents:

cp -r config config.backup

Helpful options:

  • cp -i prompts before overwriting an existing destination.
  • cp -v displays what is being copied.
  • cp -n prevents overwriting on implementations that support it.

For example:

cp -iv app.conf backups/

Before copying configuration files on a production server, verify both the source and destination paths.

5. Move or rename files with mv

Linux uses mv for both moving files and renaming them.

Rename a file:

mv README.txt README-old.txt

Move a file into a directory:

mkdir archive
mv README-old.txt archive/

Rename a directory:

mv config config-old

Use -i to prompt before overwriting an existing destination:

mv -i deploy.sh archive/

Copy vs. move

cp source dest

Creates a copy. The original remains.

mv source dest

Moves the item or changes its name.

6. Delete files with rm

Deletion is the command group that deserves the most caution.

Delete one file:

rm old.txt

Ask for confirmation:

rm -i old.txt

Remove an empty directory:

rmdir empty-folder

Remove a directory and its contents:

rm -r old-project

Production safety rules

Pause before deleting

  1. Confirm your current location with pwd.
  2. Inspect the target with ls -lah -- old-project.
  3. Use a test directory while learning.
  4. Prefer rm -i when you need confirmation.
  5. Avoid experimenting with rm -rf, wildcards, or variables in production.

rm -r can recursively delete a directory tree. rm -f suppresses many prompts and ignores missing files; it does not make deletion safer.

8. Realistic DevOps case study

Scenario: You need to prepare a deployment script and keep a copy before making changes.

Practise in your home directory, not in a production directory.

Step 1 — Create a practice project

mkdir -p ~/devops-lab/lesson3/myapp
cd ~/devops-lab/lesson3/myapp
touch deploy.sh app.conf

Step 2 — Verify what exists

pwd
ls -lah

Step 3 — Create a configuration backup

cp -i app.conf app.conf.bak
ls -l app.conf app.conf.bak

Step 4 — Archive the deployment script

mkdir -p archive
mv -i deploy.sh archive/

Verify both locations:

ls -lah
ls -lah archive/

Step 5 — Remove only the temporary backup, if appropriate

ls -l -- app.conf.bak
rm -i -- app.conf.bak

If the confirmation prompt appears, make sure the filename is the intended one before confirming.

DevOps lesson: A .bak file is useful, but it is not a complete backup strategy. For production, validate the backup, preserve appropriate permissions and ownership, and make sure there is a tested recovery process.

Remember

  • mkdir and touch create directories and files.
  • cp copies; the original remains.
  • mv moves or renames.
  • rm deletes; there is usually no Trash to recover files from.
  • Always verify paths and destinations before changing production files.
