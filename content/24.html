Module 1, Lesson 23 — Web Servers (Nginx) on Linux

Level: Intermediate · Estimated time: 35–45 minutes · Practical focus: serving websites

In this lesson, you’ll learn how to install and configure Nginx, serve a static website, manage the service with systemd, set up a basic reverse proxy, and troubleshoot a web server that isn’t responding.

1. What is Nginx?

Nginx (pronounced “engine-x”) is a high-performance web server, reverse proxy, and load balancer. It’s widely used in production to serve websites and forward traffic to application backends.

Common use cases:

  • Serve static files (HTML, CSS, images).
  • Reverse proxy to an application (Node.js, Python, Go).
  • Terminate TLS/SSL.
  • Load balance across multiple backend servers.

2. Install Nginx on Ubuntu

sudo apt update
sudo apt install -y nginx

Start and enable Nginx:

sudo systemctl start nginx
sudo systemctl enable nginx

Check status:

sudo systemctl status nginx

Test the default page:

curl http://localhost

You should see the default “Welcome to nginx!” page.

3. Important Nginx files and directories

Path Purpose
/etc/nginx/nginx.conf Main configuration
/etc/nginx/sites-available/ Site definitions
/etc/nginx/sites-enabled/ Enabled sites (symlinks)
/var/www/html/ Default web root
/var/log/nginx/ Access and error logs
/etc/nginx/mime.types MIME type mappings

Nginx reads configuration from nginx.conf, which includes files in sites-enabled/.

4. Serve a static website

Create your site files:

sudo mkdir -p /var/www/myapp/html
echo "<h1>Hello from Linotutor</h1><p>Running on Nginx.</p>" | sudo tee /var/www/myapp/html/index.html

Create a site configuration:

sudo tee /etc/nginx/sites-available/myapp <<'EOF'
server {
    listen 80;
    server_name myapp.local;

    root /var/www/myapp/html;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
EOF

Enable the site:

sudo ln -s /etc/nginx/sites-available/myapp /etc/nginx/sites-enabled/myapp

Test the configuration:

sudo nginx -t

If it says “syntax is ok” and “test is successful”, reload Nginx:

sudo systemctl reload nginx

Test with curl:

curl -H "Host: myapp.local" http://localhost

5. Manage the Nginx service

sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx
sudo systemctl reload nginx
sudo systemctl status nginx

Use reload after config changes (zero-downtime where possible). Use restart only when necessary.

6. Basic reverse proxy

Forward traffic to a backend application on port 3000:

sudo tee /etc/nginx/sites-available/myapp <<'EOF'
server {
    listen 80;
    server_name myapp.local;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
EOF

sudo nginx -t
sudo systemctl reload nginx

7. Firewall access (UFW)

Allow HTTP traffic:

sudo ufw allow 'Nginx Full'

Check status:

sudo ufw status

9. Realistic DevOps case study: website returns 404

Scenario: You deployed a site, but visiting it returns “404 Not Found”.

Investigate methodically:

# 1. Is Nginx running?
sudo systemctl status nginx

# 2. Is the config valid?
sudo nginx -t

# 3. Is the site enabled?
ls -l /etc/nginx/sites-enabled/

# 4. Does the web root and file exist?
ls -l /var/www/myapp/html/index.html

# 5. Check the error log
sudo tail -n 30 /var/log/nginx/error.log

Common causes: wrong root path, missing index file, site not symlinked into sites-enabled, or a typo in server_name.
