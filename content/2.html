Module 1 · Lesson 2: Understanding the Linux Filesystem

Level: Beginner · Estimated time: 25–35 minutes · Practical focus: navigating a Linux server

In this lesson, you'll learn how Linux organizes files, where configuration and log files live, and how to find the right file when an application fails.

1. What is the Linux filesystem?

Think of the filesystem as a tree of folders and files. Unlike Windows, where you commonly see separate drives such as C:\ and D:\, a typical Linux system organizes its files under a single root directory represented by /.

Linux filesystem tree

/

Root directory

/etc

System configuration

/home

User directories

/var

Logs and changing data

/usr

Programs and shared resources

/opt

Optional application software

/tmp

Temporary files

Simplified overview. These directories have different purposes; their exact contents vary by Linux distribution and installed software.

Remember: / is the root of the filesystem. It is not the same as /root, which is the home directory of the root administrator account.

2. The directories every DevOps engineer should know

Directory Purpose Practical example
/ Filesystem root Starting point for absolute paths
/home Regular users' home directories /home/student
/root Root user's home directory /root/.ssh
/etc System and application configuration /etc/ssh/sshd_config
/var/log Many system and application logs /var/log/syslog on many Ubuntu systems
/var Variable data, logs, caches, queues /var/lib
/tmp Temporary files Temporary scripts or working files
/usr/bin Many installed user commands /usr/bin/grep
/usr/sbin Many administrative commands Utilities for system administration
/bin and /sbin Essential commands; often linked into /usr on modern distributions ls, sh
/opt Optional or third-party application software /opt/myapp
/dev Device files /dev/null
/proc Virtual filesystem exposing process and kernel information /proc/meminfo
/sys Kernel and device information /sys/class
/mnt and /media Common mount locations Mounted disks and removable media

Two important distinctions:

  • /etc usually contains configuration, not the application logs themselves.
  • /var/log is a common log location, but some applications log to the system journal or to a custom directory.

3. Absolute paths vs relative paths

An absolute path starts at /. A relative path is interpreted from your current working directory.

Visual example

Current directory

/home/student

Documents/

notes.txt

Absolute

/home/student/Documents/notes.txt

Identifies the path from /.

Relative

Documents/notes.txt

Works from /home/student.

Useful navigation shortcuts:

  • . means the current directory.
  • .. means the parent directory.
  • ~ usually expands to the current user's home directory.
  • / means the filesystem root.

For example:

pwd
cd ..
pwd
cd ~
pwd

The output depends on where you start, but the sequence shows how to inspect your location, move up one directory, and return to your home directory.

4. Hands-on command lab

Let's learn how to navigate and inspect the filesystem.

Step 1 — Find your current location

pwd

Example output:

/home/student

This tells you the current working directory.

Step 2 — List files and directories

ls
ls -l
ls -a
ls -lh
Command What changes?
ls Basic listing
ls -l Detailed information
ls -a Includes hidden entries
ls -lh Detailed listing with human-readable sizes

Linux filenames beginning with a dot, such as .bashrc, are hidden from the ordinary ls listing.

Step 3 — Navigate safely

cd /var/log
pwd
ls

You have now moved to the common location for system logs.

Return home:

cd ~

Step 4 — Inspect a file without changing it

less /etc/hostname

Press q to exit less.

For a small text file, you can also use:

cat /etc/hostname

Step 5 — Find a file

find /etc -name "hostname" 2>/dev/null

This searches /etc for a file named hostname. The redirection suppresses permission-related error messages; it does not grant additional permissions.

DevOps tip: start with pwd, then inspect with ls, and only then navigate or edit. This simple habit prevents many mistakes.

6. Real-world case study: Website logs are missing

Incident: Find the application logs

A website is reporting errors. A teammate asks you to find the system logs and check whether Nginx has an application log directory.

Your starting information

  • Operating system: Ubuntu server
  • System logs may be in /var/log
  • Nginx logs are often stored under /var/log/nginx/, if installed and configured that way
  • You must inspect files before making any changes

Which command is the best first step to inspect the common system log directory?

cd /var/log followed by ls

rm -rf /var/log

chmod -R 777 /var/log

reboot

Check diagnosis

A professional investigation workflow

After locating the directory, you might run:

ls -lah /var/log
ls -lah /var/log/nginx
systemctl status nginx
journalctl -u nginx --since "30 minutes ago"

The second command may report that the directory does not exist. That is useful evidence, not proof by itself that Nginx is broken. The service may be uninstalled, configured to log elsewhere, or not have created those files.

The lesson: locate, inspect, collect evidence, and verify before changing the system.

9. Cheat sheet — Linux filesystem

Essential commands

Command Purpose
pwd Print current directory
ls -la List all entries with details
cd /path Change to a specified directory
cd .. Move to parent directory
cd ~ Move to home directory
cat file Display file contents
less file Read a file interactively
file filename Identify file type
stat filename Inspect file metadata
find /path -name "name" Search by filename
du -sh /path Estimate directory disk usage
df -h Inspect filesystem space usage

Copy command reference

Quick directory reference

If you need to find… Start with…
SSH configuration /etc/ssh/
System logs /var/log/ or journalctl
User files /home/username/
Temporary files /tmp/
Kernel information /proc/ and /sys/
Installed commands /usr/bin/
Application data Often /var/lib/ or an application-specific path

Production safety rule: never delete or recursively change permissions on a system directory just to investigate a problem. Begin with read-only inspection and make changes only when the cause is understood.
