Module 1, Lesson 24 — Linux Kernel, Boot Process and Troubleshooting

Level: Intermediate · Estimated time: 35–45 minutes · Practical focus: startup and recovery

In this lesson, you’ll learn how the Linux boot process works, the role of the kernel and init system, how to inspect boot logs, and how to troubleshoot a system that won’t boot or starts slowly.

1. The Linux boot process (simplified)

Power on  -->  BIOS/UEFI  -->  Bootloader (GRUB)  -->  Linux kernel  -->  init (systemd)  -->  services  -->  login
  1. BIOS/UEFI — firmware that performs a power-on self-test and finds the boot device.
  2. GRUB — the bootloader that loads the kernel into memory.
  3. Kernel — initializes hardware, mounts the root filesystem, and starts init.
  4. systemd (init, PID 1) — starts services and brings the system to a usable state.

2. The kernel and its version

Check the running kernel:

uname -r
uname -a

List installed kernels:

ls /boot

The file /boot/vmlinuz-* is the compressed kernel. initrd/initramfs-* is a temporary root filesystem used during early boot.

3. systemd — init and service manager

systemd is PID 1 on most modern Linux systems. It starts services in parallel and manages their state.

Common systemd commands:

systemctl status nginx
systemctl start nginx
systemctl stop nginx
systemctl restart nginx
systemctl enable nginx
systemctl disable nginx
systemctl list-units --type=service --state=failed

Check boot time:

systemd-analyze
systemd-analyze blame

blame shows which services took the longest to start — useful for slow-boot troubleshooting.

4. Inspect boot and kernel logs

Kernel ring buffer:

dmesg
dmesg | less
dmesg -T        # human-readable timestamps

systemd journal for the current boot:

journalctl -b
journalctl -b -1      # previous boot
journalctl -u nginx   # a specific service

The kernel log is stored in /var/log/kern.log on some systems, but dmesg and journalctl are the standard tools.

5. GRUB and boot options

GRUB configuration:

cat /etc/default/grub
sudo update-grub     # apply changes on Ubuntu/Debian

Common GRUB_CMDLINE_LINUX_DEFAULT additions:

  • nomodeset — disable graphics driver loading (fixes black screen on boot).
  • single or systemd.unit=rescue.target — boot into rescue mode.

After editing /etc/default/grub, always run sudo update-grub and reboot to test.

6. Boot targets

systemd uses targets instead of old runlevels:

systemctl get-default        # current default target
systemctl set-default multi-user.target   # text mode
systemctl set-default graphical.target    # desktop

Common targets:

  • graphical.target — multi-user + GUI.
  • multi-user.target — multi-user, text mode.
  • rescue.target — minimal system for repair.
  • emergency.target — even more minimal.

7. Troubleshooting a system that won’t boot

If Linux won’t start normally:

  1. Reboot and hold Shift (BIOS) or Esc (UEFI) to open the GRUB menu.
  2. Select “Advanced options” and try a previous kernel version.
  3. If that fails, boot into rescue.target by editing the GRUB entry (press e) and adding systemd.unit=rescue.target.
  4. In rescue mode, filesystems may be read-only. Remount writable:
mount -o remount,rw /
  1. Check logs:
journalctl -xb
dmesg | less
  1. Common fixes:
    • Fix /etc/fstab entries for missing disks (a bad fstab entry can prevent boot).
    • Reset a forgotten password with passwd.
    • Reinstall GRUB from a live USB if the bootloader is broken.

9. Realistic DevOps case study: server is stuck at boot

Scenario: After a disk was added and an /etc/fstab entry was created, the server won’t boot and drops to an emergency shell.

Recovery steps:

  1. Reboot into GRUB, edit the boot entry, add systemd.unit=rescue.target, boot.
  2. Remount root read-write: mount -o remount,rw /.
  3. Inspect fstab: cat /etc/fstab.
  4. Comment out the bad disk line (prepend #).
  5. Reboot normally.

Never delete fstab lines blindly — verify the device UUID first with blkid.

11. Cheat sheet — boot and kernel

Task Command
Kernel version uname -r
Boot messages dmesg -T
Current boot journal journalctl -b
Previous boot journal journalctl -b -1
Service logs journalctl -u <service>
Boot time systemd-analyze
Slow services systemd-analyze blame
Failed services systemctl list-units --type=service --state=failed
Default target systemctl get-default
GRUB defaults /etc/default/grub
Update GRUB sudo update-grub
Remount root rw mount -o remount,rw /

Safety tip: Before editing /etc/fstab or GRUB config, make a backup copy so you can restore it from a rescue shell.
