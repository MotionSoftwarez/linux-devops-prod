Module 1, Lesson 21 — Git Essentials on Linux

Level: Beginner · Estimated time: 30–40 minutes · Practical focus: version control on a Linux server

In this lesson, you’ll learn how to initialize a Git repository, track changes, commit work, inspect history, and collaborate using remotes. Git is a day-to-day DevOps tool for managing application code, infrastructure-as-code, and configuration files on Linux.

1. What is Git?

Git is a distributed version-control system. Every developer has a full copy of the repository history, so you can work offline and sync later.

Think of Git like a save-game system for your code:

  • Commit — save a snapshot with a message.
  • Branch — create a parallel timeline to experiment safely.
  • Merge — combine work from different timelines.
  • Remote — a copy of the repository on another machine (GitHub, GitLab, Bitbucket, or your own Linux server).

2. Install Git

On Ubuntu:

sudo apt update
sudo apt install git

Verify the installation:

git --version

Configure your identity (do this once per machine):

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Check your settings:

git config --list

3. Create and inspect a repository

Initialize a new repository:

mkdir -p ~/devops-lagit/myapp
cd ~/devops-lagit/myapp
git init

This creates a hidden .git directory. Git now tracks this folder.

Check status:

git status

4. Track and commit changes

Create a file:

echo "# My App" > README.md

Stage the file:

git add README.md

Commit with a message:

git commit -m "Add initial README"

View history:

git log --oneline

See what changed before committing:

git diff

5. The typical Git workflow

working directory  --git add-->  staging area  --git commit-->  repository
  1. Edit files in your working directory.
  2. git add the files you want to include.
  3. git commit -m "message" to save a snapshot.
  4. Repeat.

6. Undoing and fixing mistakes

Unstage a file (keep changes in working directory):

git restore --staged app.conf

Discard changes in a file (revert to last commit):

git restore app.conf

Safety: git restore destroys uncommitted changes in that file. Use it only when you’re sure.

7. Working with branches

Create and switch to a new branch:

git checkout -b feature/nginx-config

List branches:

git branch

Switch back to main:

git checkout main

Merge a feature branch into main:

git checkout main
git merge feature/nginx-config

Delete a merged branch:

git branch -d feature/nginx-config

8. Remotes and collaboration

Add a remote repository:

git remote add origin https://github.com/yourname/myapp.git

Push your commits:

git push -u origin main

Fetch and merge changes from a remote:

git pull

Clone an existing repository:

git clone https://github.com/yourname/myapp.git ~/myapp

10. Realistic DevOps case study: track an application configuration

Scenario: You manage an Nginx configuration file /etc/nginx/sites-available/myapp. You want to track changes to it with Git so you can roll back if a change breaks the site.

Do not edit files directly in /etc for your first attempt. Practise in a copy:

mkdir -p ~/devops-lagit/nginx-lab
cp /etc/nginx/sites-available/myapp ~/devops-lagit/nginx-lab/myapp.conf 2>/dev/null || echo "server { listen 80; }" > ~/devops-lagit/nginx-lab/myapp.conf
cd ~/devops-lagit/nginx-lab
git init
git add myapp.conf
git commit -m "Initial Nginx config"

Later, if you edit the config and something breaks:

git log --oneline
git show <commit-id>
git restore --source=HEAD~1 myapp.conf
