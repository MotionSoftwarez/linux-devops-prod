Create, Copy, Move, and Delete Files

Beginner

Hands-on lab

DevOps essentials

In this lesson, you’ll learn how to create directories and files, copy configuration files, rename or move files, and delete unwanted files safely. These are everyday tasks when managing Linux servers, application deployments, logs, and backups.

1. The five essential commands

Command What it does Example
mkdir Creates a directory mkdir reports
touch Creates an empty file if it doesn't exist touch notes.txt
cp Copies files or directories cp app.conf app.conf.bak
mv Moves or renames files mv old.txt new.txt
rm Deletes files or directories rm old.txt

Think of a Linux directory like a folder in a filing cabinet:

  • mkdir — create a new folder.
  • touch — create a blank document.
  • cp — make a duplicate.
  • mv — relocate or rename an item.
  • rm — remove an item.

3. Create directories with mkdir

A directory is simply a container for files and other directories.

mkdir project
ls

The mkdir project command creates a directory named project in the current working directory. ls lets you verify that it exists.

Create nested directories

mkdir -p project/config/nginx

The -p option creates missing parent directories as needed. It also avoids an error when those directories already exist.

Visual result

project/
└── config/
└── nginx/

Useful checks:

pwd
ls -l
ls -ld project
  • pwd shows where you are.
  • ls -l lists directory contents in long format.
  • ls -ld project shows information about the directory itself.

4. Create files with touch

touch notes.txt
touch app.conf
touch deploy.log

These commands create empty files if they don't exist. If a file already exists, touch generally updates its modification timestamp; it does not erase its contents.

You can create multiple files in one command:

touch app.conf app.conf.bak deploy.sh

To verify:

ls -l

Important: touch does not write text into a file. To add content, you can use an editor such as nano, or a command such as:

echo "APP_ENV=development" > app.conf

Be careful with >: it creates the file if needed but overwrites existing contents. To append instead, use >>.

5. Copy files with cp

The cp command creates a copy of a file. It's especially useful before editing a configuration file or preparing a deployment.

Copy one file

cp app.conf app.conf.bak

This creates app.conf.bak in the current directory while keeping app.conf unchanged.

Copy a file into another directory

mkdir backups
cp app.conf backups/

Result:

Current directory

app.conf

Original file remains here.

Copy into backups/

backups/

app.conf

Independent copy of the file.

Copy a directory

Use -r (recursive) to copy a directory and its contents:

cp -r config config.backup

This copies the config directory and its contents into a new directory named config.backup.

Safe copying practices

cp -i app.conf app.conf.bak
cp -n app.conf app.conf.bak
  • cp -i asks before overwriting an existing destination.
  • cp -n prevents overwriting an existing destination on implementations that support it.

If your shell supports it, cp -v displays what is being copied:

cp -v app.conf backups/

DevOps habit: Before copying files into a production configuration directory, check the source and destination paths carefully.

6. Move and rename files with mv

Linux uses the same command for moving a file to a different location and renaming it.

Rename a file

mv notes.txt notes-old.txt

The file now has the new name notes-old.txt.

Move a file to another directory

mkdir archive
mv notes-old.txt archive/

The file is now inside archive/.

Rename a directory

mv config config-old

The directory is renamed, provided the destination and permissions allow it.

Important difference: copy versus move

cp source dest

Source stays. Destination becomes a copy.

mv source dest

Source is relocated or renamed.

Protect against accidental replacement:

mv -i notes.txt archive/

The -i option asks before overwriting a destination. Always inspect the target path before moving files, especially when running commands as root.

7. Delete files and directories with rm

Deletion deserves extra care because command-line deletions usually bypass the desktop Trash.

Delete a file

rm notes-old.txt

Ask before deleting

rm -i notes-old.txt

Delete an empty directory

rmdir empty-folder

rmdir works only when the directory is empty.

Delete a directory and its contents

rm -r old-project

The -r option recursively removes the directory and its contents.

Production safety warning

Never run a destructive command until you have verified the target. In particular, avoid experimenting with rm -rf on system paths, wildcards, or variables whose values you haven't checked.

Before deletion, inspect:

pwd
ls -lah -- old-project

If you are unsure, list the intended files first, confirm the path, and use a test directory instead of a production directory.

What does -f mean?

rm -f forces removal without prompting for confirmation in typical circumstances and ignores missing files. It does not make deletion safer. Avoid combining powerful options casually, especially with elevated privileges such as sudo.

9. Realistic DevOps case study: safely preparing a deployment

Scenario: An application is deployed from /srv/myapp. Before changing the deployment script, the engineer wants to make a backup, prepare an archive folder, and keep the process auditable.

Use a practice directory in your home folder first:

mkdir -p ~/devops-lab/myapp
cd ~/devops-lab/myapp
touch deploy.sh

Check what exists:

pwd
ls -lah

Create a backup and verify it:

cp -i deploy.sh deploy.sh.bak
ls -l deploy.sh deploy.sh.bak

Create an archive directory and move the original script:

mkdir -p archive
mv -i deploy.sh archive/

Check both locations:

ls -lah
ls -lah archive/

If the backup is no longer needed, inspect it and then remove it:

ls -l -- deploy.sh.bak
rm -i -- deploy.sh.bak

The -- marks the end of command options for these commands, which helps when a filename begins with a hyphen. It does not protect against an incorrect path.

Production lesson: A file named .bak is only a backup copy, not a complete backup strategy. For production deployments, verify the backup's contents, permissions, ownership, and recovery procedure before making changes. Use approved deployment paths and follow your team's change process.

11. Practical assignment

Complete this assignment in a Linux terminal, preferably in a test environment or your home directory. Do not practise destructive commands on production files.

Assignment checklist

0 of 7

1. Create the practice structure

mkdir -p ~/devops-lab/lesson3/config

2. Create three files

touch ~/devops-lab/lesson3/config/app.conf ~/devops-lab/lesson3/config/deploy.sh ~/devops-lab/lesson3/config/README.txt

3. Create a backup copy

cp -i ~/devops-lab/lesson3/config/app.conf ~/devops-lab/lesson3/config/app.conf.bak

4. Rename the README file

mv -i ~/devops-lab/lesson3/config/README.txt ~/devops-lab/lesson3/config/README-old.txt

5. Create an archive and copy the script

mkdir -p ~/devops-lab/lesson3/archive && cp -i ~/devops-lab/lesson3/config/deploy.sh ~/devops-lab/lesson3/archive/

6. Verify the results

find ~/devops-lab/lesson3 -maxdepth 3 -type f -print

7. Clean up only the test directory, after verifying its path

ls -lah ~/devops-lab/lesson3

The final step is a verification step, not a deletion command. Once the path and contents are confirmed, you may optionally remove the test directory using a carefully checked command.

Remember these rules

  • Create: mkdir, touch
  • Duplicate: cp
  • Relocate or rename: mv
  • Delete: rm, rmdir
  • Verify: pwd, ls -lah
  • Stay safe: check the path, inspect the destination, and make a verified backup before production changes.
